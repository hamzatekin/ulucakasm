# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Static marketing/information site for a Turkish family health center (Aile Sağlığı Merkezi), served at https://ulucakasm.com. All user-facing content is in Turkish. Built with Astro 7 (SSG, no server runtime), Tailwind CSS v4, and TypeScript. There is no test suite and no backend — output is fully static HTML.

## Commands

Package manager is **pnpm** (Node >= 22.12). `.npmrc` sets `shamefully-hoist=true` for Astro deps.

```bash
pnpm install
pnpm dev        # local dev server
pnpm build      # production build to ./dist
pnpm preview    # preview the production build
pnpm typecheck  # astro check (type + template diagnostics)
pnpm pretty     # prettier (with the Astro plugin) --write over src
pnpm wrangler dev  # after `pnpm build`: serve ./dist the way Cloudflare Workers does (headers, 404, redirects)
```

There is no lint or test command. Run `pnpm typecheck` to validate changes.

## Map

The contact map is first-party end to end: no script, tile, font or API call goes to a map company, so it needs no key or consent. `scripts/map/render.mjs` (its own `package.json`, not part of the site build) reads the latest Protomaps OpenStreetMap build and writes (a) `public/map/`: the z12–z15 vector tiles for about 14 × 13 km around `LOCATION` as plain `tiles/{z}/{x}/{y}.mvt` files (Workers static assets don't serve Range requests, so no `.pmtiles` archive), the light and dark styles, the sprites and the glyph ranges for Turkish, and (b) `src/assets/images/map/map-{light,dark}.webp`, a 1120×720 picture at 2x of the opening view, drawn from those same files. `Maps.astro` shows the picture at its own size (the box crops it, so labels never shrink) with the pin on its centre and the `© OpenStreetMap` credit ODbL requires. When the section comes within 400px of the viewport, its script dynamically imports MapLibre GL JS (bundled, ~440 KB gzipped incl. worker; the CSS is injected as a `?url` link so it never lands in `<head>`), fades the live map in over the picture at the same zoom, and moves the pin into a `Marker`. Without JS or on failure the picture stays. `cooperativeGestures` keeps one-finger drags and plain wheel scrolling on the page; `maxBounds` comes from the style's source `bounds`. Run `pnpm --dir scripts/map install && pnpm --dir scripts/map render` (uses installed Chrome, or `CHROMIUM_PATH`; behind a proxy add `NODE_USE_ENV_PROXY=1`) and commit both outputs when `LOCATION` changes. Directions go out through the `DIRECTIONS` links (Google, Apple, Yandex), which only send anything once the visitor clicks.

## Deployment

Hosted on **Cloudflare Workers with static assets** (no Worker script). `wrangler.jsonc` points `assets.directory` at `./dist`, sets the custom 404 (`not_found_handling: "404-page"`) and the default trailing-slash handling, and enables `workers.dev` Preview URLs. Workers Builds is connected to the repo: build command `pnpm build`; pushes to `main` run `npx wrangler deploy` (production), other branches run `npx wrangler preview`, which posts a Preview URL (`<branch>-ulucakasm.<account>.workers.dev`) on the PR. The custom domains (`ulucakasm.com`, `www`) are attached in the dashboard, so `wrangler.jsonc` has no `routes` key; adding one would make every deploy rewrite them. Response headers live in `public/_headers` (Workers sends none of Pages' old defaults on its own).

## Architecture

- **`src/pages/`** — one `.astro` file per route: `index.astro` (home), `bagisiklama.astro` (vaccination schedule), `beslenme.astro` (nutrition), `erisilebilirlik.astro` (accessibility statement), `kvkk.astro` (KVKK aydınlatma metni). Pages compose components inside `<Layout title="Page name" description="…">`; Layout supplies the header, `<main>` and footer. `kvkk.astro` lists every third-party request the site makes (only Cloudflare, the host; the map is served from this site) — update it whenever you add or remove one.
- **`src/layouts/Layout.astro`** — the single HTML shell: `<head>` (viewport with `viewport-fit=cover`, per-scheme `theme-color`, favicons), native cross-document view transitions (declared in `global.css`), then `Header`, `<main id="main-content">` and `Footer` around the page. `title` is the page name (the clinic name is appended; omit it on the home page); `description` is required.
- **`src/components/`** — presentational section components (`Hero`, `Services`, `Doctors`, `Contact`, `Gallery`, `Header`, `Footer`, `Maps`, etc.). The home page is assembled by stacking these. Inner pages open with `PageIntro` (back link, section name, h1, optional lead slot). `Gallery` owns its single photo viewer `<dialog>`.
- **`src/lib/clinic.ts`** — single source of truth for the clinic's facts: `NAME` / `SHORT_NAME`, `ADDRESS`, `PHONES`, `LOCATION` (the map image's centre) + `DIRECTIONS` (Google / Apple / Yandex route links), `telHref`, and the family-doctor roster (`DOCTORS`: slug, name, birim `code`, phone, assistant, weekday `hours` used in each schedule's screen-reader summary). Change a phone or address here, not in components. `slug` must match the image filenames under `assets/images/asm/doctors/<slug>.webp` and `.../schedules/<slug>_schedule.webp`, which `Doctors.astro` resolves via `import.meta.glob`.

### Conventions

- **Images**: use Astro's `<Image>` from `astro:assets` with sources under `src/assets/images/` (mostly `.webp`). Astro's `<Image>` already defaults to `loading="lazy"` and `decoding="async"`, so only pass `loading="eager"` (plus `fetchpriority="high"` for the LCP image). `Img.astro` wraps an image with a click-to-open, tap-to-zoom `<dialog>` lightbox (vanilla JS, no framework); pass `label` (+ `hint`) to render a compact row trigger instead of a full-width thumbnail. `downloads/` holds working/source images and is not part of the site.
- **Icons**: inline SVGs live in `Icon.astro` as a small name-keyed registry (`map-pin`, `phone`, `external`, `arrow`, `clock`, `menu`, `close`, `expand`), all 24px stroke icons sharing one `<svg>` wrapper; add new icons there rather than importing an icon library.
- **Design system** (based on Emil Kowalski's design-engineering skills, github.com/emilkowalski/skills): Tailwind **v4**, CSS-first — no `tailwind.config.*` file. The plugin is wired via `@tailwindcss/vite` in `astro.config.mjs`; all tokens, base styles, and reusable component classes live in `src/styles/global.css`. Calm clinical surfaces, green for actions, Ministry red only for the seal. Colors: `canvas` (page bg), `surface`/`surface-2` (cards / fills), `ink`/`ink-2`/`ink-3` (text, all ≥4.5:1 on their surfaces), `accent`/`accent-strong`/`accent-soft`/`on-accent` (brand green), `seal` (Ministry red), `hairline`. Light + dark both come from `prefers-color-scheme`: the dark values override the same `--color-*` vars on `:root`, so utilities need no `dark:` variants. Depth uses the `--elev-1`/`--elev-2`/`--elev-btn*` translucent shadows, never solid borders. Type: the system font stack (no webfonts), with `text-display` / `text-title` / `text-lead` theme sizes that carry their own tracking and leading; use `tabular-nums` for phone numbers and codes. Reusable classes in `@layer components`: `.wrap`/`.wrap-tight` (safe-area-aware containers), `.card` / `.card-link` (radius 20px; inner media uses 12px with `p-2` so the radii stay concentric), `.btn-primary`/`.btn-secondary`/`.btn-ghost`, `.chip`, `.ulink`, `.lightbox`/`.lightbox-close` (the `<dialog>` shell, backdrop and close button shared by `Img` and the gallery viewer). Section headings are two-tone (`ink` statement + `ink-3` sentence) instead of eyebrow labels.
- **Motion rules** (from the Kowalski skills): animate only `transform`/`opacity` (plus `box-shadow`/colour for state), never `transition: all`; use the `--ease-out` / `--ease-in-out` / `--ease-drawer` curves from `@theme`; UI motion stays under 300ms and exits are faster than entrances; every pressable gets `:active { scale(0.97) }`; hover styles are gated to `(hover: hover) and (pointer: fine)` (the `hover:` variant is redefined in `global.css` to do this); enter animations use `@starting-style` (popover menu, dialogs), never `scale(0)`; reduced motion keeps fades and drops movement. The only page-load animation is the hero stagger. Home-page headings and cards carry `.reveal`: a small script at the end of `Layout.astro` hides the ones still below the fold (`data-reveal`) and, via IntersectionObserver, plays a one-off 600ms fade and 24px `translate` rise as each comes into view, staggering a row 60ms apart (Kowalski's scroll-reveal recipe: marketing surfaces only, fire once). Content already on screen is never hidden, and without JS or in print everything shows. Animate `translate`, not `transform`, so the `:active` press scale still works. Keep it off inner reading pages.
- **Tailwind v4 gotchas**: content scanning is automatic. A component-scoped `<style>` that uses `@apply` must start with `@reference '../styles/global.css';` (see `Header.astro`) — and must NOT be `is:inline`, or the `@apply` ships uncompiled to the browser. When adding a component class in `@layer components`, don't `@apply` another custom class (v4 only reliably `@apply`s utilities) — share base rules via a selector list instead (see `.btn-*`).
- **Formatting**: Prettier (`prettier-plugin-astro`) with `printWidth: 140`, single quotes, 2-space indent; run `pnpm pretty`.
